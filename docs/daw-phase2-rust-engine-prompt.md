# 간이 DAW — 2단계: Rust 오디오 엔진 구현 프롬프트

> 아래 전체를 에이전트에 그대로 전달하세요. 1단계 산출물(Tauri + React UI)이 이미 존재하는 상태를 전제합니다.

---

## 목표

1단계에서 만든 `WebAudioEngine`을 **Rust 네이티브 오디오 엔진(`RustEngine`)으로 완전히 대체**한다. UI 컴포넌트와 Zustand 스토어는 **한 줄도 수정하지 않는다.** `IAudioEngine` 계약을 그대로 구현하는 것이 이번 단계의 성공 기준이다.

동시에 내장 이펙터 5종을 Rust DSP로 새로 구현한다. Web Audio 노드에 의존하던 기존 이펙터는 전량 폐기한다.

## 왜 바꾸는가 (설계 판단의 근거로 삼을 것)

- Web Audio는 OS 오디오 스택(WASAPI 공유 모드)만 사용 가능해 지연이 크고 오디오 인터페이스를 직접 제어할 수 없다.
- 향후 3단계에서 VST3 호스팅을 붙이려면 오디오 그래프의 소유권이 네이티브 측에 있어야 한다.

## 기술 스택 (고정)

**Rust 측 (`src-tauri/`)**
- `cpal` — 오디오 디바이스 I/O. **기본 빌드는 WASAPI/CoreAudio/ALSA만.** ASIO는 옵셔널 피처.
- `symphonia` — 오디오 파일 디코딩 (wav, mp3, flac, ogg, aac)
- `rubato` — 샘플레이트 변환
- `hound` — wav 인코딩 (익스포트용)
- `rtrb` 또는 `ringbuf` — 락프리 SPSC 링버퍼 (제어 스레드 → 오디오 스레드 명령 전달)
- `triple_buffer` — 오디오 스레드 → 제어 스레드 상태 전달 (미터 등)
- `serde` — IPC 직렬화
- **DSP는 외부 크레이트 금지.** EQ/컴프/딜레이/리버브/웨이브셰이퍼 전부 직접 구현한다.

**TypeScript 측**
- 기존 그대로. `src/engine/rust/RustEngine.ts`를 새로 만들고 `createEngine()` 팩토리의 반환만 교체한다.

## ASIO 라이선스 처리 (반드시 준수)

ASIO SDK는 GPLv3다. 기본 빌드에 포함시키면 앱 전체가 GPLv3 의무를 지게 된다.

- `Cargo.toml`에 `asio = ["cpal/asio"]` 옵셔널 피처를 정의하고 **기본 피처에 넣지 않는다.**
- ASIO 관련 코드는 전부 `#[cfg(feature = "asio")]`로 격리한다.
- `README.md`에 "ASIO 빌드는 GPLv3 적용 대상"임을 명시한다.
- 피처가 꺼진 빌드에서는 UI의 ASIO 항목이 아예 노출되지 않아야 한다.

VST3 SDK는 2025년 10월부터 MIT 라이선스이므로 3단계에서 제약이 없다. 이번 단계에서는 사용하지 않는다.

# A. 스레드 아키텍처

이 섹션이 **이번 단계에서 가장 중요하다.** 여기가 틀어지면 소리가 지직거리고, 컴파일은 통과하므로 발견도 늦어진다.

## 세 개의 스레드

```
[웹뷰 스레드]  React UI
     │ Tauri invoke / event
[제어 스레드]  명령 해석, 그래프 구성, 에셋 디코딩, 메모리 할당
     │ 락프리 링버퍼 (SPSC)
[오디오 스레드] cpal 콜백. 실시간 데드라인 있음.
```

## 오디오 스레드 절대 금지 사항

콜백 안에서 아래를 하면 **드롭아웃(클릭 노이즈)이 발생한다.** 예외 없다.

- 힙 할당 / 해제 — `Vec::new`, `Box::new`, `String`, `format!`, `.clone()`, `.collect()`, `to_vec()`
- 락 — `Mutex`, `RwLock` (`try_lock`도 금지. 실패 시 오디오가 끊긴다)
- 시스템 콜 — 파일 I/O, 로깅, `println!`, `dbg!`
- `Drop` 실행 — 해제될 값을 오디오 스레드에서 떨어뜨리지 않는다
- 채널 `recv()` 같은 블로킹 연산
- panic 가능 연산 — 인덱싱은 `get()` 또는 사전 검증, `unwrap()` 금지

**모든 버퍼는 사전 할당한다.** 최대 채널 수, 최대 블록 크기, 최대 트랙/이펙트 수를 상수로 정의하고 초기화 시점에 전부 잡아둔다.

## 제어 → 오디오 통신

명령을 열거형으로 정의하고 링버퍼로 밀어 넣는다. 오디오 스레드는 콜백 시작부에서 큐를 비운다.

```rust
enum AudioCommand {
    SetTransport(TransportState),
    SeekTo { sample_pos: u64 },
    SetTrackGain { track_idx: usize, gain: f32 },
    SetTrackPan { track_idx: usize, pan: f32 },
    SetTrackMute { track_idx: usize, muted: bool },
    SetSendGain { send_idx: usize, gain: f32 },
    SetEffectParam { effect_ref: EffectRef, param: ParamId, value: f32 },
    SetEffectBypass { effect_ref: EffectRef, bypassed: bool },
    SwapGraph(Box<AudioGraph>),   // 아래 참조
}
```

**그래프 교체 규칙**: 트랙/이펙트/클립 구조가 바뀌면 제어 스레드가 새 `AudioGraph`를 **완성해서** 통째로 넘긴다. 오디오 스레드는 포인터만 교체하고, **이전 그래프는 반환 채널로 되돌려 보내 제어 스레드에서 drop한다.** 오디오 스레드에서 절대 drop하지 않는다.

파라미터 변경(볼륨, 노브)은 그래프 교체 없이 개별 명령으로 처리한다. 이게 실시간 조작의 기본 경로다.

## 오디오 → 제어 통신

미터 값, 실제 플레이헤드 위치, xrun 카운터를 `triple_buffer`로 퍼블리시한다. 오디오 스레드는 쓰기만, 제어 스레드는 읽기만. 웹뷰는 이 값을 **30Hz로 폴링**한다. 오디오 콜백마다 IPC 이벤트를 쏘지 않는다.

## 데놈럴 대책

리버브와 필터의 꼬리 부분에서 데놈럴 수가 발생하면 CPU가 수십 배 느려진다. 반드시 처리한다.

- 오디오 스레드 시작 시 x86에서 FTZ/DAZ 플래그를 설정한다 (`_MM_SET_FLUSH_ZERO_MODE`, `_MM_SET_DENORMALS_ZERO_MODE`).
- 추가 안전장치로 피드백 경로 상태 변수에 `if x.abs() < 1e-20 { x = 0.0 }` 처리를 넣는다.

## 파라미터 스무딩

게인, 팬, 모든 이펙트 연속 파라미터는 **원폴 스무더**를 거친다. 값을 즉시 바꾸면 클릭 노이즈가 난다.

```rust
struct Smoother { current: f32, target: f32, coeff: f32 }
// coeff = exp(-1 / (time_sec * sample_rate)), 기본 스무딩 시간 10~20ms
// next(): current += (target - current) * (1 - coeff)
```

블록 단위가 아니라 **샘플 단위로 갱신**한다. 필터 계수처럼 재계산이 비싼 경우에만 블록 단위 보간을 허용한다.

# B. 오디오 그래프와 트랜스포트

## 신호 흐름

```
클립 리더 → 클립 게인/페이드 → [트랙 인서트 체인] → 팬 → 트랙 페이더
                                     │                      │
                              (pre-fader 센드)        (post-fader 센드)
                                     └──────┬───────────────┘
                                            ↓
                                        [버스] → 버스 인서트 → 버스 페이더
                                            │
        트랙 페이더 출력 ───────────────────┴──→ 마스터 → 마스터 인서트 → 출력
```

솔로 처리: 하나라도 솔로가 켜져 있으면 솔로가 아닌 트랙은 뮤트된 것으로 간주한다. 버스는 솔로 로직에서 제외한다.

## 시간 표현

**모든 내부 시간은 `u64` 샘플 단위**로 다룬다. 초 단위 부동소수점은 IPC 경계에서만 변환한다. 긴 세션에서 f64 누적 오차가 클립 정렬을 어긋나게 만든다.

## 클립 재생

- 클립 이벤트를 시작 샘플 기준으로 정렬해 보관한다. 매 블록마다 전체를 순회하지 말고, **커서 인덱스**를 유지해 현재 블록에 걸치는 구간만 처리한다.
- 블록 경계에 걸친 클립 시작/종료는 **샘플 정확도로** 처리한다. 블록 시작으로 반올림하지 않는다.
- 페이드 인/아웃과 클립 게인은 샘플 단위로 적용한다. 페이드 커브는 equal-power(사인) 기본, 선형 옵션 제공.
- 시크 시 재생 중인 클립 상태를 리셋하고 커서를 재탐색한다.

## 루프

루프 종료 지점에서 시작 지점으로 되돌 때, **블록 중간에서 끊긴다.** 블록을 두 구간으로 쪼개 처리한다. 경계에서 짧은 크로스페이드(2~5ms)를 넣어 클릭을 막는다.

## 디바이스 관리

- 사용 가능한 호스트(백엔드) 목록과 각 호스트의 출력 디바이스 목록을 열거하는 커맨드 제공
- 샘플레이트, 버퍼 크기 선택 UI 제공. 버퍼 크기는 디바이스가 지원하는 범위 내에서 제시.
- 현재 지연시간(ms)을 계산해 표시: `buffer_size / sample_rate * 1000` + 디바이스 보고 지연
- 디바이스 분리/오류 시 스트림을 정리하고 UI에 알린 뒤, 기본 디바이스로 폴백을 시도
- xrun(언더런) 발생을 카운트해 UI에 표시. 사용자가 버퍼 크기를 조정할 근거가 된다.
- 프로젝트 샘플레이트와 디바이스 샘플레이트가 다르면 에셋 로드 시 `rubato`로 프로젝트 레이트에 맞춰 리샘플링해 저장한다. 실시간 리샘플링은 하지 않는다.

# C. 에셋 로딩과 파형

## 디코딩 (제어 스레드, 비동기)

1. `symphonia`로 디코드 → f32 planar(채널별 `Vec<f32>`)로 메모리에 적재
2. 프로젝트 샘플레이트와 다르면 `rubato`로 변환
3. 멀티 LOD 피크 계산 — 각 LOD는 `(min, max)` 쌍의 배열
   - LOD 0: 256 샘플/포인트, LOD 1: 1024, LOD 2: 4096, LOD 3: 16384
4. 로드 완료를 이벤트로 프론트에 통지 (긴 파일은 진행률도 함께)

## 피크 전송

피크 배열은 크므로 JSON 숫자 배열로 보내지 말 것. **f32 바이너리를 base64로 인코딩**해 전송하고, JS에서 `Float32Array`로 복원한다. 요청 시 특정 LOD만 선택적으로 보낼 수 있게 한다.

`IAudioEngine.loadAudioFile()`의 반환 타입 `AudioAssetInfo`는 1단계와 동일하게 유지한다. **UI는 무엇이 바뀌었는지 알 수 없어야 한다.**

## 메모리

에셋은 제어 스레드가 `Arc<AudioAsset>`로 소유하고, 그래프에 그 핸들을 담아 오디오 스레드로 넘긴다. 오디오 스레드는 읽기만 한다. 언로드 시 그래프에서 제거한 뒤 제어 스레드에서 해제한다.

# D. DSP 구현 (5종, 전부 직접 구현)

공통 규약:

```rust
trait DspEffect: Send {
    fn prepare(&mut self, sample_rate: f32, max_block: usize, channels: usize);
    fn process(&mut self, buf: &mut AudioBuffer);   // in-place, 할당 금지
    fn set_param(&mut self, id: ParamId, value: f32);
    fn reset(&mut self);                            // 상태 초기화 (정지/시크 시)
    fn tail_samples(&self) -> usize;                // 익스포트 시 꼬리 길이
    fn latency_samples(&self) -> usize;             // 오버샘플링 등의 지연
}
```

모든 필터 상태는 **채널별로 독립 보관**한다. 스테레오를 모노 상태로 처리하면 위상이 망가진다.

## 1. 파라메트릭 EQ (유동 밴드, 최대 6)

- 밴드 개수는 런타임에 1~6 사이에서 가변. 각 밴드 개별 활성/비활성.
- 밴드 타입: `Bell`(피킹), `LowShelf`, `HighShelf`, `HighPass`, `LowPass`, `Notch`
- 파라미터: `freq`(20Hz~20kHz, 로그), `gain_db`(-24~+24, shelf/bell만), `q`(0.1~18)
- HPF/LPF는 슬로프 선택 (12/24/36/48 dB/oct) — 12dB 섹션을 캐스케이드해 구현
- 계수는 **RBJ Audio EQ Cookbook** 공식을 사용. 구현은 **Transposed Direct Form II** biquad.
- 파라미터 변경 시 계수를 매 샘플 재계산하지 말고, 블록 시작에 재계산 후 이전 계수와 블록 내 선형 보간
- 미사용 밴드는 처리 자체를 건너뛴다 (계수를 unity로 두고 연산하지 말 것)

**주파수 응답 커브 API**: UI의 EQ 곡선 표시를 위해, 현재 계수로 `H(e^{jω})` 크기를 로그 간격 주파수 포인트(기본 256개)에서 평가해 dB 배열로 반환하는 커맨드를 제공한다. 이 계산은 **제어 스레드에서** 수행한다. 밴드별 개별 곡선과 합성 곡선을 모두 반환한다.

## 2. 컴프레서

- 파라미터: `threshold_db`(-60~0), `ratio`(1:1~20:1, ∞ 옵션), `attack_ms`(0.1~200), `release_ms`(5~2000), `knee_db`(0~24), `makeup_db`, `auto_makeup`(bool), `detection`(Peak | RMS), `stereo_link`(bool)
- 구조: 사이드체인 신호 → 검출기 → 게인 컴퓨터(로그 도메인) → 스무딩 → 게인 적용
- **로그 도메인 게인 컴퓨터**를 사용한다. 선형 도메인 비율 계산은 니 처리가 지저분해진다.
- 소프트 니: threshold 기준 ±knee/2 구간에서 2차 보간
- 검출기 계수: `attack_coeff = exp(-1 / (attack_ms * 0.001 * sample_rate))`, release도 동일 형태
- RMS 검출은 윈도우 평균이 아니라 원폴 제곱 평균으로 구현 (할당 없음)
- `stereo_link`가 켜지면 두 채널의 검출 신호 중 큰 값을 공통으로 사용
- 게인 리덕션 값(dB)을 미터용으로 퍼블리시

## 3. 딜레이

- 파라미터: `time_ms`(1~2000) 또는 `sync`(BPM 동기, 1/1~1/32, 점음표·셋잇단 포함), `feedback`(0~0.98), `mix`(0~1), `ping_pong`(bool), `damping_hz`(피드백 경로 LPF, 1k~20k), `stereo_offset_ms`(좌우 시간 차)
- 원형 버퍼 + **분수 지연 보간**. 선형 보간이 아니라 4점 Catmull-Rom 또는 allpass 보간을 쓴다. 시간 파라미터를 실시간으로 움직였을 때 아티팩트가 크게 줄어든다.
- 딜레이 타임 변경 시 읽기 포인터를 급격히 점프시키지 말고 스무딩한다 (테이프 딜레이 유사 피치 벤딩 허용).
- 핑퐁: 좌 입력 → 우 딜레이 → 좌 딜레이 → 순환
- 피드백 경로에 원폴 LPF를 넣어 반복마다 고역이 감쇠하게 한다.
- 버퍼는 최대 딜레이 타임(2초) 기준으로 사전 할당.

## 4. 리버브 — FDN (Feedback Delay Network)

Schroeder/Freeverb보다 밀도와 품질이 좋고, 구현 난이도도 감당 가능하다.

- 구조: 8개 지연 라인 + 8×8 **Hadamard 행렬** 피드백
- 지연 길이는 **서로소인 소수**로 선택 (예: 1447, 1637, 1777, 1949, 2137, 2287, 2411, 2557 샘플 @48kHz 기준. 다른 샘플레이트에서는 비례 조정)
- 각 지연 라인 출력에 **댐핑 원폴 LPF** 삽입 → 고역이 먼저 사라지는 자연스러운 감쇠
- 파라미터:
  - `pre_delay_ms`(0~200) — 별도 지연 버퍼
  - `size`(0~1) — 지연 길이 스케일
  - `decay_sec`(0.1~20) — RT60. 각 라인의 피드백 게인을 `g_i = 10^(-3 * len_i / (decay * sr))`로 산출
  - `damping`(0~1) — LPF 컷오프 매핑
  - `diffusion`(0~1) — 입력단 allpass 체인(4단) 계수
  - `width`(0~1) — 스테레오 확산
  - `mix`(0~1)
- 지연 라인에 **저주파 LFO 변조**(±0.5~2 샘플, 라인마다 다른 레이트)를 걸어 금속성 링잉을 줄인다. 변조 읽기는 분수 지연 보간 사용.
- 입력단에 diffusion allpass 체인을 두어 초기 반사 밀도를 확보한다.
- Hadamard 행렬 곱은 빠른 버터플라이 연산으로 구현한다 (곱셈 없이 덧셈/뺄셈 + 정규화 상수).
- **데놈럴 처리를 반드시 넣는다.** 리버브 꼬리가 데놈럴 지옥의 주범이다.

## 5. 웨이브셰이퍼

- 파라미터: `drive_db`(0~48), `curve`(enum), `output_db`, `mix`(0~1), `oversample`(1x/2x/4x), `dc_block`(bool)
- 커브 종류: `Tanh`, `SoftClipCubic`(x - x³/3, 클램프), `HardClip`, `Arctan`, `Foldback`, `Asymmetric`(양·음 비대칭)
- **오버샘플링을 반드시 구현한다.** 비선형 처리는 앨리어싱을 만들고, 오버샘플링 없는 디스토션은 쓸 수 없는 소리가 난다.
  - 업샘플 → 셰이핑 → 로우패스 → 다운샘플
  - 폴리페이즈 FIR 또는 하프밴드 필터로 구현. 계수는 초기화 시 계산.
  - `latency_samples()`에 필터 지연을 정확히 보고할 것
- 셰이핑 후 **DC 블로커**(원폴 하이패스, ~5Hz) 적용. 비대칭 커브가 DC 오프셋을 만든다.
- 드라이브를 올려도 체감 음량이 급등하지 않도록 커브별 자동 레벨 보정 옵션 제공

---

# E. 지연 보상 (PDC)

오버샘플링 웨이브셰이퍼처럼 지연을 유발하는 이펙트가 체인에 있으면 트랙 간 위상이 어긋난다.

- 각 이펙트의 `latency_samples()`를 합산해 트랙별 총 지연을 구한다.
- 전체 트랙 중 최대 지연을 기준으로, 각 트랙에 `max_latency - track_latency` 만큼의 지연 버퍼를 삽입한다.
- 그래프 재구성 시 재계산한다.
- UI에 현재 보상 지연량을 표시한다.

---

# F. 익스포트 (오프라인 렌더)

- 실시간 스트림과 **동일한 그래프·동일한 DSP 코드**를 사용한다. 별도 렌더 경로를 만들면 결과가 달라진다.
- 오디오 스레드가 아닌 별도 워커 스레드에서 실행하고, 블록 단위로 최대 속도로 돌린다.
- 렌더 시작 전 모든 이펙트에 `reset()` 호출.
- 프로젝트 끝 지점 이후 `max(tail_samples())` 만큼 더 렌더해 리버브/딜레이 꼬리를 담는다.
- 출력: `hound`로 wav 작성. 비트뎁스 선택(16/24/32f), 샘플레이트 선택.
- 진행률을 프론트에 이벤트로 통지. 취소 가능.
- 노멀라이즈 옵션, 클리핑 경고 표시.

---

# G. IAudioEngine 구현 매핑

1단계 인터페이스를 그대로 구현한다. 각 메서드가 어떤 Tauri 커맨드로 내려가는지 정리한다.

| 인터페이스 메서드 | 처리 방식 |
|---|---|
| `init()` | 디바이스 열거 + 스트림 시작 |
| `loadAudioFile()` | 비동기 커맨드. 디코딩·리샘플링·피크 계산 후 `AudioAssetInfo` 반환 |
| `syncGraph()` | 스냅샷 → `AudioGraph` 빌드 → `SwapGraph` 명령 |
| `play/pause/stop/seek` | 트랜스포트 명령 (링버퍼) |
| `getPlayheadSec()` | 캐시된 폴링 값 반환 (동기, IPC 없음) |
| `onPlayhead()` | 30Hz 폴링 루프에 콜백 등록 |
| `setTrackVolume` 등 | 개별 파라미터 명령. **그래프 재구성 없음** |
| `getTrackLevel()` | 폴링된 미터 스냅샷에서 읽기 (동기) |
| `capabilities()` | `supportsExternalPlugins: false` 유지 (3단계에서 true) |
| `scanPlugins()` | 3단계 대비 스텁 유지 |
| `renderOffline()` | 3단계 대비 스텁 유지 |

**`getPlayheadSec()`와 `getTrackLevel()`은 동기 메서드다.** 매 호출마다 IPC를 때리면 안 된다. 백그라운드 폴링으로 최신 값을 캐시하고 그 값을 반환한다.

## 추가 커맨드 (1단계에 없던 것)

디바이스 설정은 UI에 새 화면이 필요하므로 인터페이스를 확장한다. `IAudioEngine`에 아래를 추가하고, 1단계 UI에 "오디오 설정" 다이얼로그를 새로 만든다.

```ts
listAudioBackends(): Promise<AudioBackendInfo[]>;   // { id, name, available }
listOutputDevices(backendId: string): Promise<AudioDeviceInfo[]>;
getAudioSettings(): Promise<AudioSettings>;
setAudioSettings(s: AudioSettings): Promise<void>;  // { backendId, deviceId, sampleRate, bufferSize }
getStreamStatus(): StreamStatus;                    // { latencyMs, xruns, running, error? }
```

`WebAudioEngine`은 이번 단계에서 삭제한다. 다만 `IAudioEngine` 인터페이스 파일은 그대로 유지한다 — 3단계에서도 계약은 같다.

# H. 테스트

DSP는 눈으로 검증이 안 되므로 테스트가 필수다.

- **EQ**: 각 밴드 타입에 대해 임펄스 응답 → FFT → 이론 응답과 비교 (허용 오차 0.1dB). 계수 안정성(극점이 단위원 내부) 검증.
- **컴프레서**: 알려진 입력 레벨에 대한 정적 게인 곡선이 이론값과 일치하는지. attack/release 시상수가 목표 시간의 63% 지점에 도달하는지.
- **딜레이**: 임펄스 입력 후 지정 시간에 정확히 피크가 나타나는지. 분수 지연 정확도.
- **리버브**: RT60 측정값이 설정값의 ±15% 이내인지. 출력이 발산하지 않는지(무한 루프 안정성).
- **웨이브셰이퍼**: 사인파 입력 시 오버샘플링 on/off 간 앨리어싱 성분 차이 측정. 지연 보고값이 실측과 일치하는지.
- **스케줄링**: 블록 크기를 32/64/128/256/512/1024로 바꿔가며 렌더한 결과가 **샘플 단위로 동일**한지. 이게 통과하면 블록 경계 처리가 정확하다는 강한 증거다.
- **실시간 안전성**: 오디오 콜백 경로 함수들에 대해 할당 검출 테스트를 붙인다 (커스텀 글로벌 얼로케이터로 오디오 스레드 할당 시 카운터 증가 → 테스트에서 0인지 확인).

# I. 작업 순서

각 단계마다 빌드가 통과하고 앱이 실행되는 상태를 유지한다.

1. `cpal`로 사인파 출력 — 디바이스 열거, 스트림 시작/정지, 설정 UI
2. 스레드 아키텍처 골격 — 링버퍼, 명령 열거형, 그래프 스왑, 트리플 버퍼 미터
3. `symphonia` 디코딩 + `rubato` 리샘플링 + 피크 계산 + IPC 전송
4. 클립 스케줄링 + 트랜스포트 (재생/시크/루프). **이 시점에 1단계 UI로 소리가 나야 한다.**
5. 트랙 게인/팬/뮤트/솔로 + 미터링 + 스무딩
6. 센드/버스 라우팅
7. DSP — EQ (+ 응답 곡선 API)
8. DSP — 컴프레서 (+ GR 미터)
9. DSP — 딜레이
10. DSP — 리버브
11. DSP — 웨이브셰이퍼 (+ 오버샘플링)
12. 지연 보상(PDC)
13. 오프라인 익스포트
14. ASIO 피처 플래그 분리 + 문서화
15. 테스트 정비, `WebAudioEngine` 삭제, README/아키텍처 문서 갱신

**4번이 최대 관문이다.** 여기까지 오면 나머지는 점진적으로 붙는다.

# J. 하지 말 것

- 오디오 콜백 안에서 할당·락·로깅·`unwrap()`
- `Mutex<AudioGraph>` 같은 공유 상태로 스레드 간 통신
- 오디오 스레드에서 값을 drop
- DSP 외부 크레이트 도입 (직접 구현이 목적)
- 오버샘플링 없는 웨이브셰이퍼
- 익스포트용 별도 DSP 경로 작성
- ASIO를 기본 피처에 포함
- UI 컴포넌트나 Zustand 스토어 수정 (오디오 설정 다이얼로그 신규 추가만 예외)
- 블록 시작으로 반올림한 클립 스케줄링
- 매 호출마다 IPC를 발생시키는 `getPlayheadSec()` / `getTrackLevel()`
