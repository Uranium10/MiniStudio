# 간이 DAW — 2.5단계: MIDI 트랙 & 피아노롤 프롬프트

> 2단계(Rust 오디오 엔진) 완료 상태를 전제합니다. 아래 전체를 에이전트에 전달하세요.

---

## 목표

현재 엔진은 오디오 클립만 다룬다. 여기에 **MIDI 노트 개념을 도입**하고, 노트를 편집할 **피아노롤 에디터**를 만든다.

신스 자체는 아직 설계 중이므로 이번 단계에서 구현하지 않는다. 대신 **최소한의 플레이스홀더 악기**를 넣어 노트가 실제로 소리를 내는지 검증할 수 있게 하고, 나중에 실제 신스가 코드 수정 없이 슬롯에 꽂히도록 인터페이스를 설계한다.

## 이번 단계의 성공 기준

1. 인스트루먼트 트랙에 MIDI 클립을 만들고, 피아노롤에서 노트를 그려, 재생하면 소리가 난다
2. 외부 MIDI 키보드와 컴퓨터 키보드로 연주할 수 있다
3. 노트 타이밍이 **샘플 정확도**로 맞는다 (블록 크기를 바꿔도 결과가 동일)
4. 오프라인 익스포트에 MIDI 트랙이 포함된다
5. 실제 신스를 추가할 때 스케줄러·보이스 관리·피아노롤을 건드릴 필요가 없다

# A. 데이터 모델 확장

## 트랙 타입 분기

기존 `Track`에 종류를 추가한다. 기존 오디오 트랙 동작은 그대로 유지되어야 한다.

```ts
type TrackKind = 'audio' | 'instrument';

type Track = {
  // ... 기존 필드
  kind: TrackKind;
  clips: Clip[];              // kind === 'audio'
  midiClips: MidiClip[];      // kind === 'instrument'
  instrument: InstrumentInstance | null;  // kind === 'instrument'
  // effects, sends 등은 두 종류 모두 공통
};

type MidiClip = {
  id: string;
  name: string;
  startSec: number;           // 타임라인상 위치
  durationSec: number;        // 클립 길이 (노트가 넘어가면 잘림)
  loopEnabled: boolean;
  loopStartTicks: number;
  loopLengthTicks: number;
  notes: Note[];
  ccLanes: CcLane[];          // 이번 단계에서는 데이터 구조만, UI는 벨로시티만
  transposeSemitones: number;
  velocityScale: number;      // 0~2
  muted: boolean;
  color: string | null;       // null이면 트랙 색상 상속
};

type Note = {
  id: string;
  pitch: number;              // 0~127
  velocity: number;           // 1~127
  startTicks: number;         // 클립 시작 기준
  lengthTicks: number;
  releaseVelocity: number;    // 기본 64
  muted: boolean;
};

type CcLane = { cc: number; points: { ticks: number; value: number }[] };

type InstrumentInstance = {
  id: string;
  type: string;               // 'builtin:testtone' — 나중에 'builtin:<synth>' / 'vst3:<uid>'
  params: Record<string, number>;
  bypassed: boolean;
};
```

## 시간 단위 — 틱

노트 위치는 **틱(tick)** 으로 저장한다. PPQ(quarter note당 틱)는 **960** 으로 고정한다.

- 960은 3, 4, 5, 6, 8로 나누어떨어져 셋잇단·다섯잇단·32분음표를 정수로 표현할 수 있다.
- 클립 내부는 전부 틱. 엔진이 재생 시점에 `tick → sample`로 변환한다.
- 변환은 템포를 반영해야 한다. 이번 단계에서는 **고정 BPM만** 지원하고, 템포 오토메이션은 범위 밖으로 둔다. 다만 변환 함수를 `TempoMap` 구조체 뒤에 감춰서 나중에 가변 템포를 넣을 때 호출부를 안 고치게 한다.

```rust
struct TempoMap { /* 지금은 단일 bpm */ }
impl TempoMap {
    fn ticks_to_samples(&self, ticks: u64) -> u64;
    fn samples_to_ticks(&self, samples: u64) -> u64;
}
```

## 프로젝트 파일 호환

기존 프로젝트 파일에 `kind` 필드가 없다. 로드 시 없으면 `'audio'`로 간주한다. 프로젝트 포맷 버전 번호를 도입하고 마이그레이션 함수를 둔다.

# B. 악기 인터페이스 (Rust)

## 이벤트 모델 — VST3 규격에 맞춰 설계

4단계에서 VST3 인스트루먼트를 붙일 때 재설계가 없도록, 이벤트 구조를 VST3와 동형으로 만든다.

```rust
#[derive(Clone, Copy)]
struct NoteEvent {
    sample_offset: u32,   // 현재 블록 내 오프셋 — 샘플 정확도의 핵심
    kind: NoteEventKind,
}

enum NoteEventKind {
    NoteOn  { note_id: i32, pitch: u8, velocity: f32, tuning_cents: f32 },
    NoteOff { note_id: i32, pitch: u8, velocity: f32 },
    PolyPressure { note_id: i32, pitch: u8, pressure: f32 },
    Controller { cc: u8, value: f32 },
    PitchBend { value: f32 },       // -1..1
    AllNotesOff,
}
```

- `note_id`는 노트 온/오프를 짝지어 식별한다. 같은 피치를 겹쳐 눌렀을 때 올바른 보이스를 끄기 위해 필수다. 피치만으로 매칭하면 안 된다.
- `velocity`는 0~1 f32로 정규화해 전달한다 (MIDI 0~127을 나눔).
- `tuning_cents`는 지금 항상 0. MPE/마이크로튜닝 확장 여지로 남긴다.

## Instrument 트레이트

기존 `DspEffect`와 나란히 둔다.

```rust
trait Instrument: Send {
    fn prepare(&mut self, sample_rate: f32, max_block: usize);
    fn process(&mut self, events: &[NoteEvent], out: &mut AudioBuffer);
    fn set_param(&mut self, id: ParamId, value: f32);
    fn reset(&mut self);                    // 정지/시크 시 전 보이스 즉시 소거
    fn tail_samples(&self) -> usize;        // 릴리즈 꼬리
    fn active_voice_count(&self) -> usize;  // UI 표시용
}
```

`process`에 넘어오는 `events`는 **`sample_offset` 오름차순 정렬 보장**이며, 오프셋은 항상 `0..block_len` 범위다. 이 계약을 문서화하고 디버그 빌드에서 검증(assert)한다.

## 블록 분할 처리

악기 구현체는 이벤트 오프셋에서 블록을 쪼개 처리한다. 헬퍼를 공용으로 제공한다.

```rust
// 이벤트 경계로 구간을 나눠 순회하는 헬퍼
fn for_each_segment(events: &[NoteEvent], block_len: usize,
                    f: impl FnMut(&[NoteEvent], Range<usize>));
```

**이벤트를 블록 시작으로 반올림해 처리하는 것은 금지.** 그러면 32분음표 패시지에서 리듬이 뭉개진다.

## 보이스 관리 (공용 유틸로 분리)

개별 악기마다 다시 짜지 말고 재사용 가능한 구조로 만든다.

```rust
struct VoiceAllocator<const N: usize> { /* ... */ }
```

- 최대 폴리포니 상수 (기본 32, 파라미터로 조절)
- 보이스 상태: `Idle | Attack..Sustain (held) | Release`
- **보이스 스틸링 우선순위**: ① Idle → ② Release 중 가장 오래된 것 → ③ held 중 가장 오래된 것. 스틸 시 즉시 끊지 말고 **2~5ms 페이드아웃** 후 재할당한다 (클릭 방지).
- 서스테인 페달(CC64): 페달이 눌린 동안 노트 오프를 보류하고, 페달을 떼면 보류된 노트를 일괄 릴리즈
- `AllNotesOff` / `reset()` 시 전 보이스를 짧은 페이드로 정리 (즉시 무음화 금지)
- **할당 금지** — 보이스 배열은 사전 할당된 고정 크기

## 플레이스홀더 악기 — `builtin:testtone`

실제 신스가 나오기 전 검증용. 최소 구성으로 만들되 소리는 들을 만해야 한다.

- 오실레이터 1개, 파형 선택 (`Sine | Triangle | Saw | Square`)
- **PolyBLEP 안티에일리어싱** 적용 (Saw/Square). 이 코드는 실제 신스에서 그대로 재사용된다.
- ADSR 엔벨로프 (선형 어택, 지수 디케이/릴리즈)
- 마스터 게인, 폴리포니 설정
- 벨로시티 → 진폭 매핑 (곡선 파라미터 하나)
- 피치벤드 ±2반음 반영

**의도적으로 단순하게 유지한다.** 이 악기를 확장하지 말고, 실제 신스는 별도 구현체로 추가할 것.

# C. 스케줄링 (Rust 오디오 스레드)

## MIDI 클립 → 노트 이벤트

기존 오디오 클립 스케줄러와 같은 원칙을 따른다.

- 그래프 구성 시 각 MIDI 클립의 노트를 **시작 샘플 기준으로 정렬한 이벤트 배열**로 평탄화해 둔다. 노트 하나가 `NoteOn` + `NoteOff` 두 이벤트가 된다.
- 클립 루프가 켜져 있으면 평탄화 시점에 전개한다 (오디오 스레드에서 계산하지 않음).
- 클립 트랜스포즈·벨로시티 스케일도 평탄화 시점에 적용한다.
- 매 블록마다 **커서 인덱스**로 해당 구간의 이벤트만 수집해 `sample_offset`을 계산하고 악기에 전달한다.
- 이벤트 수집 버퍼는 사전 할당 (블록당 최대 이벤트 수 상수, 초과 시 드롭하고 카운터 증가).

## 경계 처리

- **시크/정지**: 즉시 `AllNotesOff`. 그러지 않으면 노트가 무한히 울린다(stuck note).
- **루프 되돌기**: 루프 끝에서 아직 안 끝난 노트를 오프 처리한 뒤 되돌린다.
- **클립 경계**: 노트가 클립 끝을 넘으면 클립 끝에서 오프. 클립 뮤트 시 진행 중 노트도 오프.
- **재생 시작 위치가 노트 중간일 때**: 그 노트는 재생하지 않는다 (중간부터 시작하지 않음). DAW 표준 동작.

## 실시간 입력 (라이브 연주)

외부 MIDI 및 컴퓨터 키보드 입력은 재생 여부와 무관하게 즉시 소리가 나야 한다.

- 입력 이벤트는 별도 링버퍼로 오디오 스레드에 전달
- 오디오 스레드는 블록 시작 시 이 큐를 비우고, **오프셋 0**으로 처리 (라이브 입력에 샘플 정확도는 무의미)
- 클립 재생 이벤트와 라이브 이벤트는 병합해 오프셋 순으로 정렬 후 악기에 전달
- **모니터링 대상**: 현재 선택된 인스트루먼트 트랙 (또는 녹음 암 트랙). 트랙 헤더에 모니터 상태 표시.

# D. MIDI 입력

## 외부 MIDI 디바이스

- `midir` 크레이트 사용
- 입력 포트 열거 / 선택 / 연결 커맨드 제공. 오디오 설정 다이얼로그에 "MIDI" 탭 추가.
- 여러 포트 동시 입력 허용
- 지원 메시지: Note On/Off (velocity 0인 Note On은 Note Off로 처리), Pitch Bend, CC (특히 64 서스테인, 1 모듈레이션), Channel Pressure, Program Change는 무시
- `midir` 콜백은 자체 스레드에서 오는데, **여기서 오디오 스레드용 링버퍼에 직접 push한다.** 중간에 제어 스레드를 거치지 말 것 (지연 추가).
- 디바이스 분리 감지 및 UI 알림
- MIDI 러닝 상태(running status) 및 실시간 메시지는 `midir`이 처리하므로 신경 쓰지 않음

## 컴퓨터 키보드

MIDI 기기가 없어도 테스트할 수 있어야 한다.

- 매핑: `Z S X D C V G B H N J M` = C~B (아래 옥타브), `Q 2 W 3 E R 5 T 6 Y 7 U` = 한 옥타브 위
- `Z` / `X` 키로 옥타브 시프트... 는 위 매핑과 충돌하므로, **옥타브 변경은 `,` / `.`** 로 한다. 현재 옥타브를 UI에 표시.
- 벨로시티는 고정값(기본 100), 슬라이더로 조절 가능
- **키 리피트 무시** — `keydown`이 반복 발생하므로 이미 눌린 키는 무시한다
- 텍스트 입력 필드에 포커스가 있으면 비활성
- 창 blur 시 전 노트 오프 (필수 — 안 하면 stuck note)
- 토글로 켜고 끌 수 있게 하고, 켜져 있을 때 기존 단축키와 충돌하는 키는 건반이 우선

## MIDI 녹음

- 트랙 녹음 암 → 재생 시작 → 입력이 클립으로 기록
- 카운트인 (0/1/2마디 선택)
- 녹음 중 실시간으로 노트가 클립에 쌓이는 것이 피아노롤/아레인지에 보여야 함
- 오버더빙: 기존 클립에 병합 vs 새 클립 생성 — 옵션으로 선택
- 루프 녹음은 이번 단계 범위 밖 (구조만 막아두지 말 것)
- 녹음된 노트는 퀀타이즈 없이 원본 그대로 저장. 퀀타이즈는 사후 편집으로.

# E. 피아노롤 UI

**이번 단계 작업량의 절반 이상이 여기다.** 1단계 아레인지 뷰에 준하는 규모로 다룬다.

## 배치

하단 패널에 **세 번째 탭 "에디터"** 를 추가한다 (기존: 믹서 / 디바이스).

- MIDI 클립을 더블클릭하면 에디터 탭이 열리고 해당 클립이 로드된다
- 하단 패널이 접혀 있으면 자동으로 펼친다
- 에디터 높이를 크게 쓰고 싶을 때를 위해 **패널 최대화 토글**을 제공 (아레인지를 덮음)
- 오디오 클립을 더블클릭하면 에디터 탭에 "이 클립은 편집할 수 없습니다" 안내 (오디오 에디터는 범위 밖)

## 레이아웃

```
┌─────────────────────────────────────────────────────┐
│ 툴바: 퀀타이즈 · 그리드 · 스케일/키 · 벨로시티 · 최대화 │
├──────┬──────────────────────────────────────────────┤
│      │ 타임 룰러 (마디/박)                            │
│ 건반 ├──────────────────────────────────────────────┤
│ 거터 │                                              │
│      │ 노트 그리드                                   │
│ (세로 │                                              │
│  피아 │                                              │
│  노)  │                                              │
├──────┼──────────────────────────────────────────────┤
│      │ 벨로시티 레인                                  │
└──────┴──────────────────────────────────────────────┘
```

- 세로축 = 피치(위가 높음), 가로축 = 시간
- 건반 거터: 흰건반/검은건반 구분, C음마다 옥타브 라벨(C3 등), **클릭하면 해당 음 미리듣기**, 세로 드래그로 스크롤
- 그리드 배경: 검은건반 행은 살짝 어둡게. 마디선은 굵게, 박선은 중간, 그리드선은 얇게
- 시간축 줌·스크롤은 **아레인지 뷰와 독립**. 다만 "아레인지와 동기화" 토글을 제공.
- 세로 줌(노트 높이) 조절, 기본은 노트가 있는 음역이 다 보이도록 자동 맞춤

## 도구 시스템 재사용

1단계의 `getEffectiveTool`을 **그대로 재사용**한다. 새 도구 상태를 만들지 말 것. 피아노롤에서의 해석만 다르게 한다.

| 도구 | 피아노롤에서의 동작 |
|---|---|
| `arrow` | 노트 선택·이동·길이 조절, 빈 곳 드래그 시 러버밴드 |
| `range` | 시간 구간 선택 (피치 전체 또는 드래그 범위) |
| `split` | 노트 분할 |
| `erase` | 노트 삭제, 드래그로 연속 삭제 |
| `paint` | 노트 그리기, 드래그로 길이 지정, 가로 드래그 연속 입력 |
| `mute` | 노트 뮤트 토글 |
| `listen` | 클릭한 노트 미리듣기 |

Ctrl 서브 도구도 동일하게 동작한다.

## 노트 편집

- **그리기**: `paint` 도구로 클릭 시 마지막 사용 길이로 생성, 드래그하면 길이 지정. `arrow` 도구에서도 빈 곳 더블클릭으로 생성.
- **이동**: 드래그. 세로는 반음 단위 스냅(항상), 가로는 그리드 스냅(토글 가능). 이동 중 **피치가 바뀌면 미리듣기 재생**.
- **길이 조절**: 노트 좌/우 끝 6px 이내 드래그. 커서 `ew-resize`.
- **복제**: Alt+드래그
- **다중 선택**: 러버밴드, Shift+클릭 추가, Ctrl+A 전체, 건반 거터 클릭으로 해당 피치 전체 선택
- **다중 편집**: 여러 노트 선택 후 이동/길이조절/삭제가 일괄 적용
- **미리듣기**: 노트 생성·이동 시 짧게 소리. 토글로 끌 수 있게.

## 벨로시티 레인

- 하단에 고정. 높이 조절 가능, 접기 가능.
- 각 노트마다 세로 막대. 노트와 가로 위치가 정확히 정렬되어야 함.
- 막대 드래그로 개별 조절, 여러 노트 선택 시 상대적 일괄 조절
- **선 그리기 모드**: 레인 위를 가로로 드래그하면 지나간 노트들의 벨로시티가 마우스 높이를 따라감 (램프 만들기)
- 노트 색상이 벨로시티를 반영하도록 (진하기 또는 채도)

## 퀀타이즈 & 스케일

- 그리드 설정: 1/1 ~ 1/64, 점음표·셋잇단 포함
- 퀀타이즈 실행 (선택 노트 또는 전체): **강도(%)** 와 **스윙(%)** 파라미터 포함. 100% 강도가 아니면 원위치와 그리드 사이를 보간.
- 노트 끝도 퀀타이즈할지 옵션
- **스케일 스냅**: 키(C~B)와 스케일(Major, Natural/Harmonic Minor, Dorian, Phrygian, Lydian, Mixolydian, Locrian, Pentatonic Major/Minor, Blues) 선택
  - 스케일 밖 음의 행은 배경을 어둡게 표시
  - "스케일에 맞춤" 모드가 켜지면 노트 입력·이동 시 가장 가까운 스케일 음으로 스냅

## 편집 액션 (툴바 또는 단축키)

- 트랜스포즈: ↑/↓ 반음, Shift+↑/↓ 옥타브
- 레가토 (선택 노트를 다음 노트 시작까지 연장)
- 길이 배수 조절 (×2, ÷2)
- 벨로시티 일괄 (+/- 값, 랜덤화 ±범위)
- 뒤집기: 피치 반전 / 시간 반전
- 중복 노트 제거

## 렌더링 성능

- **Canvas 2D로 그린다.** 노트를 DOM 요소로 만들면 수천 개에서 죽는다.
- 뷰포트 컬링: 화면 밖 노트는 그리지 않는다
- 노트 배열을 시작 시간 기준 정렬 상태로 유지하고, 이진 탐색으로 가시 구간을 찾는다
- 레이어 분리: 배경 그리드는 정적 캔버스, 노트는 동적 캔버스, 플레이헤드·선택 박스는 오버레이 캔버스
- 드래그 중에는 노트 레이어만 다시 그린다
- 5,000개 노트에서 60fps를 유지하는지 벤치마크할 것

## 아레인지 뷰 연동

- MIDI 클립도 아레인지에서 오디오 클립처럼 이동·복제·트리밍·분할 가능
- **클립 안에 노트 미니 프리뷰**를 그린다 (작은 막대들). 피치 범위를 클립 높이에 정규화.
- 인스트루먼트 트랙 헤더에 악기 이름 표시, 클릭 시 디바이스 탭에서 악기 파라미터 표시
- MIDI 클립 우클릭: 편집 / 복제 / 분할 / 뮤트 / 색상 / 이름 변경

---

# F. 디바이스 랙 확장

- 인스트루먼트 트랙 선택 시 디바이스 랙 **맨 왼쪽에 악기 슬롯**이 표시된다 (Ableton과 동일한 배치). 그 오른쪽이 이펙트 체인.
- 악기 슬롯은 이펙트처럼 드래그 순서 변경 대상이 아니다 (항상 체인 시작)
- 악기 교체 드롭다운. 교체 시 현재 울리는 노트를 정리하고 새 악기로 전환.
- `builtin:testtone`의 파라미터 UI: 파형 선택, ADSR 4개 노브, 게인, 폴리포니
- 활성 보이스 수를 작게 표시 (디버깅에 유용)

---

# G. 오프라인 익스포트

- MIDI 트랙이 익스포트에 포함되어야 한다
- 렌더 시작 전 악기 `reset()`
- 프로젝트 끝 이후 악기의 `tail_samples()`도 꼬리 계산에 포함
- 라이브 입력은 익스포트에 반영하지 않는다 (클립 노트만)

---

# H. 테스트

- **틱↔샘플 변환**: 왕복 변환 오차, 경계값
- **이벤트 평탄화**: 루프 전개, 트랜스포즈, 클립 경계 클리핑이 정확한지
- **블록 크기 불변성**: 블록 크기 32~1024로 바꿔 렌더한 결과가 **샘플 단위로 동일**한지. (2단계와 동일한 테스트를 MIDI 트랙 포함 프로젝트로 확장)
- **보이스 스틸링**: 폴리포니 초과 시 우선순위가 규칙대로인지, 스틸된 보이스가 클릭 없이 사라지는지
- **stuck note**: 시크·정지·루프·클립뮤트·악기교체·창blur 각 상황에서 노트가 남지 않는지. **전 케이스를 테스트로 만들 것.**
- **note_id 매칭**: 같은 피치를 겹쳐 눌렀다 하나씩 뗄 때 올바른 보이스가 꺼지는지
- **퀀타이즈**: 강도 0%/50%/100%, 스윙 적용 결과가 이론값과 일치하는지
- **피아노롤 렌더 성능**: 5,000 노트 벤치마크
- **실시간 안전성**: 2단계의 오디오 스레드 할당 검출 테스트를 MIDI 경로에도 적용

---

# I. 작업 순서

1. 데이터 모델 확장 + 프로젝트 포맷 마이그레이션 (기존 오디오 프로젝트가 깨지지 않는지 먼저 확인)
2. `Instrument` 트레이트, `NoteEvent`, `VoiceAllocator`, `TempoMap`
3. `builtin:testtone` 구현 (PolyBLEP + ADSR)
4. 컴퓨터 키보드 입력 → 라이브 이벤트 링버퍼 → 소리 확인. **여기서 처음 소리가 나야 한다.**
5. 외부 MIDI 입력 (`midir`)
6. MIDI 클립 스케줄링 (평탄화, 커서, 경계 처리, AllNotesOff)
7. 피아노롤 셸 — 건반 거터, 그리드, 스크롤/줌, 캔버스 레이어 구조
8. 노트 렌더링 + 선택 + 이동/길이조절 (`arrow`)
9. 나머지 도구 연결 (paint/erase/split/mute/listen)
10. 벨로시티 레인
11. 퀀타이즈 · 스케일 스냅 · 편집 액션
12. 아레인지 뷰 MIDI 클립 지원 + 미니 프리뷰
13. 디바이스 랙 악기 슬롯
14. MIDI 녹음
15. 익스포트 반영, 테스트 정비, 문서

**4번이 첫 관문이다.** 여기서 키보드를 눌러 소리가 나면 나머지는 UI 작업이다.

# J. 하지 말 것

- 노트 이벤트를 블록 시작으로 반올림 (샘플 정확도 필수)
- 노트 오프를 피치로만 매칭 (`note_id` 사용)
- 오디오 스레드에서 루프 전개·트랜스포즈 계산 (평탄화 시점에 처리)
- 피아노롤 노트를 DOM 요소로 렌더링
- 1단계 도구 시스템과 별개인 새 도구 상태 만들기
- 플레이스홀더 악기를 확장해 실제 신스처럼 만들기 (별도 구현체로 추가할 것)
- 보이스 스틸링 시 즉시 무음화 (페이드 필수)
- 창 blur / 정지 / 시크 시 노트 정리 누락
- 템포 변환을 호출부에 흩뿌리기 (`TempoMap` 경유)
